The current export contains no populated business CRM, football, ownership,
communication, relationship, or lifecycle rows. Its field inventory is useful
for mapping design, but it is not evidence that those categories have been
migrated or tested. The existing rehearsal mapped 10 template rows and
rejected 8 operational rows; it did not prove business-data coverage.

## Fixture implementation checkpoint

The fixture-only planner now exercises 69 sanitized rows across 63 business
source tables. All 69 rows map to deterministic V2 target identities with
complete field coverage in the dry-run payload, including the complete source
snapshot, ownership references, timestamps, statuses, foreign-key references,
relationships, provenance, and lifecycle history. Collision fixtures produce
`DUPLICATE_CANDIDATE`; unknown categories produce explicit rejects; secret
material is explicitly excluded.

The fixture apply now persists all 37 reachable V2 target types and an internal
source field ledger. A second apply reuses the same run and source keys without
duplicating rows. Fixture reconciliation verifies target rows, ownership,
foreign keys, relationships, lifecycle/history, and source coverage with zero
unexplained loss. `saved_searches` remains unsupported because no V2 destination
exists. Freeze/delta, rollback/reapply, production access, and cutover remain
deferred. No migration-specific frontend was added.

## Disposition legend

- **Partial**: the current planner has a destination, but drops fields or does not cover the complete entity shape.
- **Unsupported**: business-relevant data has no implemented, reviewed mapping.
- **Control-only**: retain redacted source metadata in migration artifacts or the migration ledger, not as a CRM row.
- **Intentional exclusion**: not business data, is derived/rebuildable, or contains credentials; the reason is explicit and must remain in reconciliation evidence.

## Completion rule

The mapping layer is not complete. It may only be declared complete after a
versioned export contains representative rows for every business-relevant
category above, every field has a reviewed disposition, ownership and foreign
keys reconcile, duplicate and merge history is preserved or explicitly
approved for exclusion, mailbox credentials remain excluded, and the final
report proves zero unexplained business-data loss. Empty tables in this export
are inventoried but do not satisfy those tests.
